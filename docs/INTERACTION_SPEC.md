# 对战、回放与导出交互规范

本规范同时记录参考行为和我们的实现目标。证据等级见 [网站拆解](WEBSITE_BREAKDOWN.md#证据等级)。当前对战、回放和片段网页的实现及验收详见 [交付验收](DELIVERY_AUDIT.md)。下文保留参考行为与此前规划的证据区分。

## 本地对战

### 开局与布局

1. 打开本地模式直接显示标准双人开局，不要求账号。
2. 棋盘显示坐标、目标边线、红蓝棋子、已放墙和当前合法目的地。
3. 面板显示双方名称、墙数、当前回合和按回合排列的棋谱。
4. 辅助操作包含声音、旋转、更多设置；对局操作包含悔棋与认输。

以上为 **UI**。

### 走棋

- 点击当前合法目的地提交一个动作，无需先选择移动工具。
- 成功时改变棋子位置、追加一个记谱、切换回合、更新合法目的地。
- 点击开局不可达的 e3，没有提交动作或增加棋谱，属于已验静默拒绝。
- 不应把“某次非法点击无提示”推广到全部错误；放墙有单独的错误提示。
- 结束后不能继续改变真实棋局。分析页试走应进入分支。

### 放墙与拖动托盘

- 点击横向或竖向墙槽直接尝试放墙，方向由墙槽决定。
- 成功只扣当前玩家一墙，同时追加 `h...` 或 `v...` 棋谱并切换回合。
- 交叉放墙已实测提示“路障不能交叉。”，不扣墙、不新增棋谱、不切换回合。
- SOURCE 还区分越界、重叠、交叉、封死路径等失败原因。
- “拖放路障”控制横墙 / 竖墙托盘的显示与隐藏，不是与点击放墙互斥的模式。
- 早期原站观察中，托盘存在和可拖动属性已验，但两次自动拖放没有提交棋谱；这只限定原站当时的观察。复刻版曾在 Chrome 模拟触控中成功放墙，新版结果见交付验收。
- SOURCE 显示拖动感应、触摸延时、取消和预览处理。精确触控手感待实机验收。

**复刻目标**：墙槽命中范围可略大于视觉墙缝；候选位置预览合法性，交叉点的方向选择必须明确。两种输入都调用同一个规则验证函数。

### 悔棋

UI 已验证 `e2,e8,he4` 连续悔三次恢复开局、双方 10 墙和空棋谱；按钮在开局禁用。

SOURCE 表明原站保存操作前完整局面与棋谱快照。本地双人撤销一个动作；电脑模式的内部逻辑考虑一次撤销双方动作，但实际专家对战界面没有显示悔棋按钮。因此不能仅凭内部 `undoMove` 推断所有模式都可悔棋。

### 认输与终局

- 第一次认输点击变为确认按钮；SOURCE 确认窗口为 4 秒，超时恢复。
- 期间发生行动也会取消待确认状态。
- 第二次确认令当前玩家认输，保存胜方和 `finishedReason=resign`。
- 自然到达终点、认输等原因需要独立展示。
- 专家自然失败局已验显示“你输了 / 电脑（专家）先抵达终点”。
- 终局可见再赛、回大厅、分析、片段和分享等入口。

### 刷新与偏好

原站本地页刷新清空当前棋局和棋谱，但保留拖放托盘展开偏好。主题和声音也有独立的存储键（SOURCE）。

**当前实现**：有行动的棋局自动保存在浏览器记录库，刷新后可恢复；界面偏好与棋局记录分别存储，恢复时校验棋谱。

## 专家人机对战

已实测专家可免登录选择；可选红方先手。已完整下过一盘 23 回合 / 46 动作的专家局，蓝方专家到 i1 获胜。

- 行动后可见短暂“思考中…”，随后更新电脑动作与玩家回合。
- **思考期间输入锁定未专门测试**，应列为复刻验收项目。
- 训练接口通过棋谱请求专家应手，不操作网页中的实际棋局。
- 专家适配器不能用于推断或宣称掌握服务端内部搜索算法。

**复刻目标**：思考中禁止重复提交同一动作；异步请求携带局面版本，晚到响应不能应用到已重置或切换的棋局。网络错误保持棋盘可解释状态，允许重试 / 重置。

## 回放

### 主线浏览

UI 已验证首步、上一步、播放 / 暂停、下一步、末步和点击记谱跳转。回看同步恢复棋子、墙数与墙体；当前动作高亮。

SOURCE 细节：

- 游标 `-1` 表示标准开局；每个索引代表一个半回合动作。
- 倍率为 0.5×、1×、2×、3×、5×，对应 2000、1000、500、333、200ms / 步。
- 普通自动播放到末尾停止；在末尾点播放会从开局重播。
- 手动导航停止自动播放；首尾禁用不可用方向按钮。
- 左 / 右单步，上到开局，下到主线末尾；Space 或 End 切换播放。
- 未选择文字时 Cmd / Ctrl+C 复制逗号分隔的主线棋谱，不含变化。
- 旋转只改变视角，不改变记谱坐标。

这些快捷键和末尾播放行为主要为 SOURCE，本轮没有逐项做键盘 UI 验收。

### 变化分支

UI 已实测：

1. 载入主线 `e2,e8,he4`。
2. 点击主线 e2，蓝方试走 f9。
3. 原主线保留，增加变化行；继续红 e3、蓝 f8，变化扩展。
4. 后退到变化第一步 f9 时，上一步禁用，不自动回到分叉点。
5. 点击变化的删除按钮，整条变化删除，恢复分叉点局面。
6. 带 `var=0:f9,e3,f8` 的链接可恢复变化并定位到变化末步。

原站 SOURCE 用“主线半回合索引 → 多条动作数组”的一层变化集合，不是任意深度棋谱树。

**复刻改进**：增加明确的“返回分叉点”；以当前选中节点为起点创建或延伸变化。原站源码存在回退后仍按分支尾部追加的边界迹象，尚未 UI 复现，不在本规范中断言为已证实缺陷。

### 普通回放与引擎分析

普通回放与试走变化可免登录使用。另点“分析对局”会触发登录要求，这是独立的引擎分析能力。

SOURCE 显示引擎面板包含最佳线路、走法等级、准确率与评价曲线；结果来自服务端。最佳线路还可作为变化加入并演示。未登录情况下未验证真实引擎结果。

### 分享与结束元数据

原站 `moves` 链接将逗号棋谱做 URI 压缩；`game` 链接读取服务端记录。纯棋谱可以恢复走法，却无法从“玩家认输”本身推出结果。已实测认输局的 moves 回放没有保留认输说明。

**复刻要求**：分享 / 导出格式应保存 `winner`、`finishedReason`、规则版本与初始配置；不能把棋盘位置当作全部终局证据。

## 视频片段导出

### 已在界面看到

独立弹窗包含浅色棋盘预览、播放 / 暂停、0..1000 进度滑块、默认 2×、视角、声音和下载按钮；主棋盘可以仍为深色。

### 源码确认

- 视频速度只有 **1×、2×、3×**，不同于普通回放五档。
- 当前画面比例状态默认 9:16，没有找到可见比例选择器。绘制器虽支持 1:1、16:9，不能据此宣称页面提供选择。
- 预览用 requestAnimationFrame、局面缓存、棋子插值和结尾停留，循环播放。
- 预览与本地导出最多取前 100 个动作，超出时有提示。
- 本地分支使用 Canvas → captureStream → MediaRecorder；默认 30fps、6Mbps；必要时 FFmpeg WASM 转为 MP4。
- 声音通过 AudioContext 混流，导出声音与游戏静音设置分开。
- 有对局编号时可走服务端导出路径；客户端也存在服务端预览分支，但未找到当前版本自然进入该预览分支的状态转移。
- 本地录制中可取消；FFmpeg 加载 / 转码阶段不显示取消，忙碌时关闭受限。

**未补验**：暂停后拖动的实际 UI 效果、关闭重开是否保留设置、视角 / 声音更新时机、最终下载文件及长视频提示。不能仅凭 React state 的初始化代码断言弹窗重开一定保留设置，过渡组件可能卸载内部内容。

**当前实现**：统一棋谱时间轴用于 720×1280 片段预览和浏览器本地录制，并提供进度、取消和失败提示；支持的实际格式取决于浏览器。原站音效资源用于走棋与放墙。新版下载、声音及画面测试结果见交付验收；多比例选择不是当前已验功能。

## 当前响应式布局

桌面回放使用独立侧栏显示双方、棋谱变化及播放控件；手机对战在棋盘上下显示玩家卡片，并提供横向、纵向拖墙入口；手机回放使用并排玩家卡片及棋盘下方控制区。具体尺寸和交互覆盖以 [交付验收](DELIVERY_AUDIT.md) 的新版测试为准。

## 本地产品首页精简

2026-11-12 按用户标注移除首页的平台扩展模块、账号卡片和 App 横幅，首页提供立即开玩、人机对战、本地对战与玩法入口。侧栏提供对局、玩法、语言与设置。手机回放导航同步精简，记录与棋谱载入通过对局和回放的更多菜单访问。实际检查范围见 [交付验收](DELIVERY_AUDIT.md)。

## 语言选择与路障颜色

本地界面支持简体中文和 English。桌面侧栏、设置页、对局更多菜单以及手机首页和回放顶部提供语言选择；偏好保存在浏览器，切换即时更新文案。品牌显示 Barricade Lab。对局与回放中的路障根据放置者分别显示为红色和蓝色。
