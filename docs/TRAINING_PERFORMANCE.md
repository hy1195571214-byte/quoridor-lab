# 本地训练输入加速

2026-11-24 检查了正在使用 MPS 的训练。瓶颈集中在 CPU 构建合法动作掩码时，对大量候选墙位逐一进行路径搜索。GPU 独立合成输入测试中，256 个样本的前向与反向计算约 3.8 ms；该数字不含优化器、数据准备和传输，不作为完整训练吞吐量。

训练编码增加了 `bitset-path-v1` 实现：以 81 位整数表示棋盘可达区域，先找到双方各自的一条到达终点路径。候选墙如果没有碰到现有路径，该方仍然可达；碰到路径时再执行可达性检查。墙的重叠、交叉、剩余数量及走棋/跳跃规则与原实现保持一致。

公共 `State.observation()` 继续作为规则参考实现。训练专用编码只改变计算方法，不改变 8×9×9 平面、209 项掩码、目标动作或样本顺序。因此沿用已有 `stream-v2` 数据指纹，批次检查点可继续使用。新进程在状态和检查点中记录 `input_pipeline=bitset-path-v1`。

## 小批实测

硬件为 M4 MacBook Air，10 核 GPU、16 GB 内存，当时另有训练进程运行。使用冻结语料的训练分区、seed 0、batch 256、缓冲区 1,024，读取并组装连续 4 批真实样本。

| 数据准备实现 | 1,024 样本耗时 | 样本/秒 |
| --- | ---: | ---: |
| 原规则逐项检查 | 4.100 秒 | 249.8 |
| 加速编码 | 0.192 秒 | 5,324.7 |

本次输入准备约加速 21.3 倍，逐批检查棋盘、掩码、动作、棋局 ID 和步数完全一致。该结果只覆盖这批输入准备，不是完整训练的固定提速倍数。原始实测记录见[性能检查记录](evidence/training-input-performance-20261124.json)。

已将加速掩码与原规则对比，覆盖随机合法局面、真实训练棋谱、墙重叠/交叉、唯一通路、边界、跳跃和终局；CPU 中途恢复一致性测试继续通过。

## 启用现有运行

正在运行的 Python 进程不会自动重载训练代码。看板会提示“加速版本已就绪”；由用户点击“暂停训练”，等待保存后显示“已停止”，再点击“继续训练”。恢复时保留最近安全检查点中的模型、优化器、训练顺序和批次位置。

读取配置或刷新网页不会暂停/恢复训练。暂停接口只对持有写入锁、进程组 ID 和命令行均匹配该运行目录的训练组发送 SIGINT；不会对其他应用发送信号。只有用户点击按钮才调用该接口。
