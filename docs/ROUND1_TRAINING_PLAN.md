> 2026-11-24 起，本页用于复现历史棋谱基线。当前首轮以本地搜索 AI 示范和 PPO 对练为起点，见 [三阶段训练流程](TRAINING_GUIDE.md#三阶段训练路线)。

## 目标与文献依据

本轮研究问题为，在当前经过检查的 2,500 盘数据上，小型策略网络能否学习未见局面的示范行动，并提高对固定本地对手的表现。

项目 P8 AlphaGo（2016）的监督策略预训练阶段提供主要方法参考，使用局面和实际行动拟合下一手概率，随后可继承权重进行强化学习。本轮采用行为克隆，后续阶段再研究胜负奖励、价值网络和 PPO。AlphaGo 的棋盘、数据规模和模型参数与本项目不同，本方案中的网络、超参数和运行预算由项目规模决定。[P8 原文](https://storage.googleapis.com/deepmind-media/alphago/AlphaGoNaturePaper.pdf) · [项目研读笔记](../references/summaries/08_ALPHAGO_2016.md)

P3 为行动掩码的策略梯度分析提供依据。项目在监督学习和实际决策中也保持同一合法动作集合，依据规则引擎屏蔽非法行动。P4 和 P6 提醒实验者区分开发选择与最终测试、记录不同种子与失败运行，并把实战表现和训练指标一起报告。[P3 原文](https://arxiv.org/abs/2006.14171) · [P4 原文](https://jmlr.org/papers/v25/23-0183.html) · [P6 项目笔记](../references/summaries/06_RELIABLE_EXPERIMENTS.md)

## 冻结的数据

本方案将“2,500 盘”定义为本轮训练、验证和测试的总语料，其中 2,000 盘用于梯度更新。Master 对 Master 和 Master 对 Expert 两个批次已按用户决定排除。

| 来源 | 训练 | 验证 | 测试 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| Expert 对 Expert | 290 | 36 | 36 | 362 |
| 公开 QuoridorGG PGN | 1,710 | 214 | 214 | 2,138 |
| 对局数合计 | 2,000 | 250 | 250 | 2,500 |
| 逐步样本数 | 111,940 | 13,781 | 14,302 | 140,023 |

Expert 对 Expert 沿用已经生成的固定划分。PGN 从去重且确认到达终点的 2,212 盘中按胜方及左右镜像完整棋谱组确定性选择 2,138 盘，剩余 74 盘的 ID 登记在清单中。选样种子为 0。样本清单记录每盘的原 ID、来源、胜方、步数和完整走法哈希。

已检查同一完整走法和它的左右镜像均处在同一分区。本轮 2,500 盘对应 2,413 个左右镜像组。共享开局和其他相似局面仍可能跨分区，离线评估同时报告训练中未出现过的观察输入子集表现。

两批数据保留双方全部经过检查的行动，按逐步样本均匀打乱训练。监督目标为实际走法。PGN 玩家身份、等级分和档位未知，导入时保留这个来源事实。1.95 GB QuoridorCPP 包已完成下载校验，内容审计及后续数据版本另外登记。

## 输入、模型和损失

沿用现有绝对棋盘视角与 `State.observation()` 的 8 个 9×9 通道，包括双方棋子、两种墙、双方剩余墙、行动方和总步数比例。第 8 通道以 256 为分母重新生成。行动编号沿用 81 个棋子目标格、64 个横墙和 64 个竖墙，共 209 个。

为每个落子前局面生成观察、目标行动及 209 项合法掩码，要求目标行动合法。将数组保存为紧凑数据文件，用批次加载训练，来源和对局 ID 随索引保留。模型输入采用 float32。本轮使用原始视角，左右镜像扩增可在后续独立实验中比较。

| 模型 | 结构 | 参数数 | 角色 |
| --- | --- | ---: | --- |
| MLP | Flatten → Linear(648,256) → ReLU → Linear(256,209) | 219,857 | 现有结构基线 |
| CNN32 | 三层 Conv2d，通道依次为 8→32→32→32，每层 3×3、padding=1 和 ReLU，随后 Flatten → Linear(2592,209) | 562,769 | 首轮主模型 |

两个网络都输出 209 个 logits，按当前合法掩码屏蔽后计算目标行动的交叉熵。胜负用于数据统计和实战评价，本轮监督损失直接拟合实际行动。

CNN 结构及约 56 万参数是本项目的初始设计。两种结构接受形状 `[batch,8,9,9]` 并输出 `[batch,209]`。监控训练入口已实现冻结棋谱的输入适配；CNN 小样本运行已验证更新、保存及预测加载，正式训练待执行。

## 初始训练配置与运行预算

| 设置 | 初始值 |
| --- | --- |
| 优化器 | AdamW |
| 学习率 | 0.0003 |
| 权重衰减 | 0.0001 |
| 批大小 | 256 |
| 轮数上限 | 每次运行 40 epochs |
| 梯度范数裁剪 | 1.0 |
| 验证频率 | 每个 epoch |
| 学习率调整 | 验证交叉熵连续 3 轮未改善时乘 0.5，最低 0.00001 |
| 早停 | 验证交叉熵连续 8 轮未改善，最小改善量 0.0001 |
| 最佳模型选择 | 当前运行中验证交叉熵最低的检查点 |
| 主模型种子 | CNN32 使用 0、1、2 |
| 结构基线种子 | MLP 使用 0 |
| 设备 | 启动时探测 CUDA、MPS、CPU，记录实际选用设备和依赖版本 |

当前工具环境中的 PyTorch 探测结果为 MPS 不可用，CPU 已通过小批更新检查。正式启动时重新探测设备，先测一个 epoch 的真实耗时，再记录整轮预算估计。资源与参数选择属于本轮探索方案。

先以种子 0 完成 MLP 与 CNN32 的探索比较，再用 CNN32 的种子 1、2 观察主模型波动，共 4 次正式运行，上限 160 epochs。每次运行独立输出，保留提前停止及失败的结果。MLP 单种子对照支持探索性比较，进一步讨论架构稳定性时需给基线增加独立训练重复。

## 评价协议

每个 epoch 记录训练与验证交叉熵、Top-1 和 Top-3 行动预测准确率，并分别统计走棋、横墙、竖墙、行动方、数据来源和未见观察子集。合法均匀随机策略的示范匹配率作为离线参照。精确行动匹配可能受到同局面多种合理行动的影响，棋力结合整盘对战解释。

开发实战评估安排在训练前及每 5 个 epoch，每个对手 40 盘，学习方执红、执蓝各 20 盘。对手为当前本地 `random` 和 `shortest`，记录版本、种子与全部棋谱。标准开局作为主协议。模型采用合法集合中的 argmax，随机性来自对手，统计中注明这一点。

网络和超参数选定后，冻结开发阶段选出的模型，对每个对手进行 200 盘最终评价，学习方执红、执蓝各 100 盘，使用独立于开发评估的对手种子，共 400 盘／运行。最终保留的 250 盘棋谱同步用于一次离线测试。保留测试结果用于本轮报告，后续版本继续登记测试使用情况。

每盘双方合计最多 256 次行动，最后一步产生赢家时按自然终局统计。报告胜、负、截断、错误及全部计划对局的分母，红蓝分别列出。胜率使用胜局数除以全部计划对局数，另报胜加半个截断的得分率，错误单独标记并按失败计入得分，附 Wilson 95% 区间。按运行分别汇报后再汇总 CNN 的三次训练，标准开局可能产生重复轨迹，相应区间用于描述固定协议下的表现。

本轮工程目标为模型可以稳定完成合法对局、保留局面学习表现改善，并在固定对手评估中优于同结构随机初始化模型。随机对手胜率达到 80%、最短路对手胜率超过 50% 作为探索目标记录，实际结论依完整结果形成。未达目标时检查来源、放墙预测、循环走法、忽略一步获胜与先后手差异，再制定下一轮实验。

## 保存、恢复与后续加数据

每次运行保存配置、数据与划分哈希、依赖版本、设备、种子、每轮日志、最新检查点、最佳检查点及开发棋谱。检查点包含架构名称与参数、编码版本、模型权重、优化器、调度器、epoch、全局步数、最佳验证指标、早停计数和随机状态。恢复边界放在 epoch 结束后。

同一数据版本中断恢复时加载全部训练状态。加入 QuoridorCPP 数据时建立新数据版本、检查与保留测试棋谱及镜像组的重叠，继承选定网络的权重，用明确登记的新优化器和较低初始学习率开展混合新旧数据实验。原数据版本与基线模型可继续参与比较。

## 实现顺序与当前状态

1. 已完成文献核对、2,500 盘选样、来源与胜方统计，以及完整棋谱和左右镜像组的划分检查。
2. 接着构建观察数组、行动与合法掩码，报告跨分区观察重合，核对全部目标合法性。
3. 为训练入口接入来源白名单、冻结划分、MLP/CNN 架构、检查点恢复及分项指标。PGN 来源标签原样保留。
4. 小批验证读取、损失、参数更新、保存加载一致性及短局评估，再按上述预算开展 4 次运行。
5. 汇总保留测试与固定对手结果，保存代表棋谱及模型，登记下一阶段的初始化模型。

原有 `train_imitation.py` 读取 `barricade:` 教师数据并自行进行 80/20 划分。新增 `train_monitored.py` 使用冻结整盘清单，已实现 MLP/CNN、合法掩码、调度、早停、完整恢复，以及 NLL、Top-1/Top-3、棋子/墙验证指标。训练看板已接入当前样本、最新保存检查点的预测和完整对战回放分支，64 个训练样本和 64 个验证样本的两轮试跑仅用于联通检查。

小样本回归检查已确认按 epoch 恢复与连续训练的最终权重一致。正式运行前仍需补齐跨分区观察重合审计、完整分项评价和固定对手实战评估。上述正式实验预算及成绩尚未执行，实际结果待运行后填写。看板与启动方式见 [训练指南](TRAINING_GUIDE.md#实时训练看板与棋谱回放)。
