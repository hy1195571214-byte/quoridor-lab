## 棋盘几何与视觉

- SOURCE `b99ebf75b97cb2f1.js:10055–10103`：棋盘为正方形、圆角 24px，默认 padding 4px，`sm` 起 16px，19×19 网格；普通轨道 `0.5fr repeat(8, 4fr 1fr) 4fr 0.5fr`，窄布局则 `0.3fr repeat(8, 4fr 0.6fr) 4fr 0.3fr`，行列相同，无 gap。尺寸受屏宽、视口高和侧栏约束，不是固定像素棋盘。
- 格子位于 grid row `2*r+2`、column `2*c+2`，圆角为格边长 16%，border 透明，轻阴影。棋子占格子 55% × 55%；移动使用格距 125%（窄布局 115%）的 transform。旋转棋盘 180°，格子内容再旋转 180°，逻辑坐标不变（同文件 10150、10395 附近）。
- 横墙 anchor `(r,c)` 占 grid row `2r+3 / 2r+4`、column `2c+2 / 2c+5`；竖墙占 row `2r+2 / 2r+5`、column `2c+3 / 2c+4`。墙的视觉形状覆盖两格及中缝，圆角小并带阴影；交叉方向的投放区域在拖动中禁用（同文件 6299–6380）。
- 常规深色主题：框 #1a1a1a，格 #2a2a2a，悬停 #333333，中性墙 #cccccc；红目标行 rgb(59,42,42)，蓝目标行 rgb(38,48,63)。浅色主题：框 slate-200、格 gray-50、墙 zinc-800，目标行分别 rgb(254,234,234)、rgb(229,240,255)。合法格深色白色微填充加浅灰 2px ring，浅色 emerald ring 和浅绿填充（同文件 3459–3498）。
- 棋子红 #ef4444、蓝 #3b82f6；分析页深色已放墙红 #b25656、蓝 #5b7fb8；普通对局的墙用主题中性色（`fd863653c9bae7ee.js:1598`；`b99...js:6150`）。最新动作格有琥珀色叠层，墙有琥珀 ring。视频主题颜色另有覆盖，不应直接使用对战配色。
- 字体基线是系统无衬线：`ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, Segoe UI, …`；本次读取的 CSS 没有发现字体 URL。颜色与 Tailwind 类的具体值应以读取到的同版本 CSS 为准。

## 操作与状态

- 棋格与墙槽分别直接点击；桌面空墙槽 hover 灰色，拖动覆盖目标呈绿色。触摸非拖动时墙槽默认不响应点击；不要只做桌面点击而宣称触屏已复刻。`b99...js:6299–6380`。
- 拖动托盘提供横、竖两个 draggable。鼠标与触摸传感器独立，触摸激活延迟 250ms，容差 8px（`b99...js:8125–8131`）；托盘 `touch-action:none`，拖动中原墙透明度 0.4–0.5。chip 模式横墙标记 32×6px、竖墙 6×32px；非 chip 为 64×6px 或 6×64px（`b99...js:6060–6130`）。支持键盘拖放文案，但准确端到端键盘行为未实测。
- 拖放和直接点选都须落到同一合法性检查，拒绝重叠、交叉、封死路径；行为级测试以 `INTERACTION_SPEC.md` 为准。拖放成功本身仍需实机验收。
- 参考脚本还有依据使用统计自动隐藏托盘的逻辑，使用 `walls_auto_hidden`（`b99...js:6884–6892`）；不要误认为这证明刷新恢复了对局。

## 回放、分享及导出

- 分享主线使用 `compressToEncodedURIComponent` 压缩逗号连接的记谱；分析页 `moves` 包含逗号时直接 split，否则解压，解压失败时将字符串视作单步（`b99...js:7008`、`d1dde131bf60bbe8.js:1500`、`fd863653c9bae7ee.js:1746`）。实现需兼容 LZ-String URI 字母表及原站生成的 URL，不能仅对 JSON 做 Base64。`game` 需依赖远程记录；纯 moves 链接不蕴含认输结果。
- 游标、键盘导航、五档速度、单层多变化及实测分叉边界见 `INTERACTION_SPEC.md`。分享复刻需同时验证空谱、原样逗号谱、压缩谱、变化恢复、无效输入；不要将分支后退行为猜测成已测结果。
- 视频弹窗独立于普通回放：预览时间轴、速度 1/2/3×、视角与独立声音选项；Canvas、MediaRecorder、可能的 FFmpeg 转码、100 步上限及服务端导出分支均为源码证据。源码中状态变量不能单独证明重开设置保留；实际下载文件和所有触控行为仍需验收。详见 `INTERACTION_SPEC.md`。

## 组件划分建议

`GameShell`（响应式两栏）→ `PlayerStatus`、`Board`（Cell / Pawn / WallSlot / WallRack）、`MoveList`、`GameActions`；`ReplayController` 持有主线游标与自动播放，`VariationList` 独立管理分叉，`ClipDialog` 从同一 replay timeline 生成画面。视角、主题和声音是展示偏好，实际局面与胜负从规则状态和历史重建。AI 接口按 action + history 对接；不要让异步模型回复直接改写已切换的局面。

以上为实现指南，不代表已验证不同屏幕所有断点、触摸手势及编码后的导出文件。界面截图比对仍需运行中验证。
