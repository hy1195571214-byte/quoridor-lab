# 本地示范采集 Dashboard

## 启动采集与回放

检出最新源码。以下 Windows PowerShell 命令从仓库根目录执行。

1. 准备 Python 环境并启动采集面板。已经装好依赖时，直接运行最后一条命令。

   ```powershell
   cd training
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install .
   .\.venv\Scripts\python.exe -m quoridor_lab.dashboard
   ```

2. 在另一个终端，从仓库根目录启动本地回放网页。

   ```powershell
   cd frontend
   npm ci
   npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
   ```

   macOS 或 Linux 可在第 1 步用 `python3 -m venv .venv`，再用 `.venv/bin/python` 替换 Windows 虚拟环境的解释器路径。回放用其他地址时，在启动 Dashboard 的命令后加 `--replay-base http://127.0.0.1:<端口>`。

3. 打开 [本地 Dashboard](http://127.0.0.1:8770/)，分别选择红方和蓝方难度，填写「运行盘数」与「同时运行盘数」。重现本次实验时选择红方 Expert、蓝方 Easy、总盘数 3、同时运行盘数 3，开局留空，勾选「每步重新请求，跳过缓存」。逐盘对照只把同时运行盘数改为 1。默认单盘最多 256 次单方行动。

## 看进度、回放和取数据

- 当前批次会显示每盘已完成的动作数和轮到哪一方。点击该盘进度可以回放已完成的走法。
- 点历史棋谱的「打开回放」，项目回放页会显示双方的 Barricade 难度。结果栏显示获胜方的档位。同档对局的 A 是红方，B 是蓝方。
- 每批默认在 `training/data/collection/dashboard/<运行编号>/`。`episodes.jsonl` 保存棋谱和终局，`transitions.jsonl` 保存逐步示范、局面张量、合法动作掩码、档位和缓存标记。面板可下载两个文件，详情目录也保存单盘 JSON。
- 「暂停采集」会停止发出新请求并保留各局检查点。服务错误或限流也会暂停当前批次。可在「恢复此批采集」上方调整同时运行盘数和请求间隔，再接着原来的棋局跑。每个 Dashboard 实例一次运行一个批次。

## 并发和请求限制

Dashboard 每批最多可填 **10,000 盘**，其中最多 **100 盘**同时保持进行中，并且同时运行盘数不能超过本批总盘数。默认同时运行 1 盘。「每条连接的盘数」留空时所有棋局共用一条连接。同批 6 盘、每连接 3 盘时，两个独立队列各轮转 3 盘，可各有 1 个应手请求在途。设为每连接 1 盘时，每个活动棋局使用自己的连接。所有连接共用同一个设备标识与全局请求间隔。间隔默认 1 秒，可设为 0.05 秒或更长。收到明确限流时暂停采集并保留检查点。

| 同时运行盘数 | 每连接盘数 | 连接数 | 全局请求间隔 | 理论发起上限 |
| ---: | ---: | ---: | ---: | ---: |
| 6 | 3 | 2 | 1 秒 | 60 次／分钟 |
| 4 | 1 | 4 | 0.35 秒 | 约 171 次／分钟 |
| 5 | 1 | 5 | 0.30 秒 | 200 次／分钟 |

100 盘和 0.05 秒是本地配置边界。Barricade 的服务端配额没有确认。6 条连接共用 0.05 秒时曾收到明确的 `rate_limited`。所有连接合计按配置的间隔发起请求，增加连接可以减少等待回复造成的空档。发出速度接近间隔上限时，继续增加连接无法提高这个上限。

Master 对 Master 实测中，四条连接共用 0.35 秒时，回复正常的窗口约为 165 条有效应手／分钟。五条连接共用 0.30 秒时，无错误的短测约为 187–196 条／分钟，另一个包含非法回复和重试的约 47 分钟窗口实测约为 118 条／分钟。每分钟有效应手只统计合法且已落盘的走法。非法应手和明确限流分别记录。

需要限制一批的采集时间时，填写「整批时间上限（秒）」。到时停止请求远端应手，保留已经取得的动作，并将已启动的未完局标为「到时截断」并保存棋谱。每分钟远端应手用采样阶段耗时计算。

用本地替身在 32 盘同时进行的配置下验证了 128 步，32 份棋谱均能重放到保存的终局。这个检查覆盖队列和数据落盘，真实服务的耗时与稳定性以远端实测为准。

## 正式采集队列

下面的 PowerShell 命令在本地 Dashboard 已启动且没有待续跑的正式队列时，建立 15 种搭配、25 个批次，共 75,000 盘。需要从空历史开始时，先暂停并归档旧目录，或启动 Dashboard 时用 `--output` 指定新的采集目录。

```powershell
$settings = @{
    games_per_matchup = 5000
    connections = 4
    request_interval = 0.35
    illegal_move_retries = 2
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8770/api/campaigns' `
    -ContentType 'application/json' -Body $settings
```

先跑 Master 对 Master，优先处理包含高档 AI 的搭配。同档对局跑 5,000 盘。不同档的搭配各执红方 2,500 盘，合计 5,000 盘。正式队列使用标准开局、关闭缓存、不设整批时间上限。每条连接一次推进一盘。

单盘重试后仍收到非法应手时，采集器记录拒绝原因并保留棋局断点。其它棋局继续推进，搁置的棋局稍后补跑。当前正式队列的调速实测保存在首批目录的 `rate-diagnostics/connection-tuning.jsonl`，采集进度和导出文件可在 Dashboard 查看。

发生可重试的连接故障时，正式队列会重新请求同一局面一次，并写入 `transport-retries.jsonl`。重试仍失败或收到明确限流时，当前批次暂停，从 Dashboard 恢复可接着原来的棋局跑。

## 逐盘与三盘轮转实测

2026 年 11 月 15 日，两批均为标准开局、Expert 红方对 Easy 蓝方、关闭缓存，各跑 3 盘。从首盘开始到末盘结束统计墙钟耗时，吞吐用远端应手数除以耗时。

| 模式 | 总耗时 | 各盘步数 | 远端应手 | 每分钟应手 | 棋谱 |
| --- | ---: | --- | ---: | ---: | --- |
| 逐盘 | 208.0 秒 | 47、35、37 | 119 | 34.3 | 3 盘均由 Expert 红方获胜，整盘无重复 |
| 三盘轮转 | 159.0 秒 | 29、39、31 | 99 | 37.4 | 3 盘均由 Expert 红方获胜，整盘无重复 |

三盘轮转这批总用时少约 49 秒（23.6%），每分钟应手多约 8.9%。这批棋总共少走 20 步，两批的远端响应速度也会波动，因此单次对照无法估计轮转调度在相同工作量下能带来多少提速。三盘轮转前九条示范按三盘轮流写入，99 条均按所属盘的历史重新验证合法性、难度和终局，没有发现串盘或采集错误。99 条记录中有 85 条唯一示范，按相同局面、难度和应手去重。
