## 数据接收与筛选要求

- 当前首轮选用 Expert 对 Expert 与公开 PGN，共 2,500 盘。按冻结名单导入，保留来源、批次与原棋局 ID。Master 对 Master 和 Master 对 Expert 两批已按用户决定排除。
- 原始文件按版本保存，逐盘重放，核对行动方、难度、合法性、掩码、观察和结果。统计缓存、重复、拒绝回复、恢复重试及结束原因。
- 依据来源白名单、逐步 `metadata.difficulty` 与整局档位选择教师。公开 PGN 的玩家与档位保留未知，导入适配须保留原始来源标签。
- 双远端采集双方均可标为 `is_teacher=true`。报告训练脚本实际接收的各档数量，确认难度筛选与预期一致。
- 按整盘划分训练、开发验证和最终测试，重复或近重复完整棋谱归组，报告跨集合局面重合与未见局面表现。固定划分后新增数据登记新版本。
- 自然终局、步数截断、时间截断、待恢复和错误分别统计。已验证的未完局行动可用于行为克隆，真实胜负结果用于相应价值标签。
- 采集提速记录涉及异常 `e2` 应手，按原始错误日志和采样窗口抽查。合法性验证与教师质量审计共同形成数据报告。[质量记录](../docs/COLLECTION_SPEED_TUNING.md)

## 两阶段训练要求

行为克隆先完成小批数据读取、更新、保存加载、合法决策和完整对战。正式训练将数据与划分清单对应，保存可用于评估和迁移的模型结构、编码、参数与必要预处理。

强化学习从已登记的行为克隆快照初始化，验证继承前后的行动分布。保存冻结的预训练对照模型。当前 REINFORCE 示例支持 `--warm-start`，PPO 迁移需实际适配策略结构与价值分支。进入新阶段时单独记录优化器和训练进度。

统一标准规则、先后手和双方合计 256 次行动上限。当前先用胜负奖励建立微调基线，对手与奖励组合在后续独立实验中比较。

训练与评估均使用对应局面的合法掩码。PPO 的旧概率来自当前批次采样，并固定用于该批更新。专家棋谱用于监督训练，PPO 更新依据当前策略的新交互。

核对终局、截断和批次边界，明确学习方视角与最终状态。用针对性案例验证，再接入相应价值处理。保存数值异常及受影响的实验版本，修复后重跑。

## 评估、监控与结论

- 行为克隆同时报告保留局面预测与固定对手完整对战，按难度、先后手、移动和放墙拆分。
- 微调前后使用相同评估协议，保留纯行为克隆模型。资源允许时加入随机初始化强化学习对照，分别报告微调预算和两阶段总成本。
- 奖励组合从同一预训练起点进行比较，固定预算与评估。五档示范顺序作为后续假设，与匹配数据使用量的混合顺序比较。
- 每个运行独立保存配置、日志、模型和棋谱。持续训练曲线与定期评估标明频率，采集面板与训练面板按实际能力登记。
- 保存全部种子与失败结果，报告胜、负、截断、错误和分母。开发评估选模型，冻结协议后运行最终保留测试。
- 每个改善结论附配置、数据、初始与最终模型、原始结果和棋谱路径，并说明运行数量及波动。

## 首轮任务与验收

请以“两台电脑的示范数据整理和行为克隆小闭环”为当前首轮任务。

1. 同步 GitHub 最新资料与相关说明，记录主源码与 Reference 版本。
2. 导入可获得的小批采集文件，生成难度、先后手、重复、结束状态和异常的审计报告。未收到的远端文件登记为待导入。
3. 执行用户确定的来源选择，适配教师导入，并使用已冻结的训练、开发验证和测试分组。
4. 运行一小段行为克隆，核对参数更新、实际数据选择、保存加载及合法行动。
5. 完成固定本地对手评估和代表棋谱回放，保存行为克隆起点报告。
6. 交付数据审计、划分清单、配置、模型、日志、棋谱、复现命令，以及强化学习权重接入方案。

验收依据是产物可追溯、标签与规则一致、数据划分可复查、模型可加载并完成评估。之后按行为克隆基线、强化学习微调、奖励与对手对照、多种子确认和最终测试推进。
