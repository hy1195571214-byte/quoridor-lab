# Agent 工作规范与首轮任务

本文件可作为交给 AI 编程 agent 的任务说明。各阶段的预算与目标在实际任务中确定，agent 在已授权范围内完成实现、验证和分析。[实验方法](EXPERIMENT_METHODS.md)

## 每轮实验开始前

写明研究问题、现象证据、预期原因、本轮主要改动、对照版本、固定条件、预算、训练种子、开发评估方案、产物路径及保留或回退标准。假设在查看该轮结果前记录，运行后产生的新解释登记为下一轮待验证问题。

## 实现与数据要求

- 确认实际导入仓库中的 `quoridor_lab` 主源码，记录代码提交或源码摘要。
- 统一规则、棋盘编码、行动编号、奖励归属、先后手和最大步数，改变条件时创建新实验配置。
- 分别记录学习方决策次数和双方行动总数，明确训练预算使用哪个口径。
- 训练和评估都应用当前局面的合法掩码，遇到非法行动保存错误与局面供诊断。
- PPO 保存采样时的行动概率，按相同掩码计算更新概率，并按批次采样和有限轮更新组织经历。
- 核对终局、截断和批次边界的处理，以及价值估计对应的行动方视角。
- 记录数值异常和实现错误，标记受影响实验，修复后在新版本重跑。

## 评估与结论要求

- 固定开发对手、先后手比例、开局、步数上限和行动选择方式。
- 保存胜、负、截断和错误，报告指标分母，检查重复棋谱。
- 保留每个训练种子，包括失败与中断情况。分别统计单个模型的对局变化和独立训练之间的变化。
- 开发评估用于选择模型。最终测试在模型与协议确定后运行，并记录测试反馈是否参与后续调参。
- 实验改动围绕主要假设，给基线合理调参机会。组合改动的结论限定在完整组合及实际测试条件。
- 每个“改善”结论附上配置、模型、原始结果和棋谱路径，说明运行数量与结果波动。

## 保存与恢复要求

每次运行使用独立编号，保存配置、依赖版本、训练日志、评估、检查点和棋谱。保留最新模型与开发评估选出的最佳模型。

完整续训需要模型、优化器、调度器、训练计数、随机状态、预处理及对手版本等信息。选择清晰的更新或回合边界保存。如果需要中途恢复，再补充环境与采样缓存的状态，并验证实际恢复行为。

## 自主执行与预算

agent 在约定阶段和预算内继续完成可逆修正与必要验证。达到预算、遇到外部依赖或需要改变目标时，提交已有证据、问题原因及具体后续方案，方便决定下一步。

每轮结束交付改动、验证结果、产物路径、未解决问题、保留或回退决定及下一轮假设。

## 首轮可直接执行的任务

请基于当前仓库建立统一的离线模型评估流程。

1. 核对现有环境、训练入口和模型格式，记录主源码与运行版本。
2. 运行现有离线测试，补充评估所需的先后手、计分、截断及模型冻结检查。
3. 适配随机合法、最短路和已有策略模型，统一应用合法掩码。
4. 先用少量对局验证加载、完整对局、结果记录与棋谱回放，测量耗时后确定扩大评估的预算。
5. 在约定预算内均衡先后手评估，保存全部结果、错误原因及重复棋谱数量。
6. 交付基线报告、配置、棋谱、复现命令和第一轮训练建议。

首轮验收关注结果可追溯、先后手计分正确、评估模型保持固定、错误可诊断、回放结局一致。后续训练沿用同一套评估方法比较进步。
