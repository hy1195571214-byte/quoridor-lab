# 实验方法、测试与模型优化

本文件把参考论文中的方法与 Quoridor 当前实现连接起来。项目状态依据 2026-11-13 检查的提交 `49a23f8`，后续训练计划按实验记录更新。以下流程属于项目实施建议，具体预算与阈值在实验开始前确定。[文献目录](README.md)

## 第一阶段核对环境

人工设计小局面检查移动、跳跃、斜跳、墙重叠、墙交叉、禁止封路和胜负。随机棋谱用于补充覆盖，检查行动编码、掩码和实际执行是否一致。先后手都应测试，确认奖励始终归属于学习方。

当前一次环境行动通常包含学习方的一步和对手的回应，单方的一步称为一个 ply。保存学习方决策次数与双方行动总数，实验比较时统一预算口径。

达到步数上限与自然获胜采用不同处理。接入 PPO 前，检查截断时返回局面轮到谁，以及价值估计对应的视角。当前实现可能在学习方行动后达到上限并跳过对手回应，结束掩码也会清零。需要根据任务定义处理最终局面、价值自举和决策边界。[实证研究设计概括](summaries/04_EMPIRICAL_DESIGN.md)

阶段交付包括环境契约、测试结果和已知问题。现有安装与测试命令见训练指南，新增命令在实现并验证后写入操作文档。[训练指南](../docs/TRAINING_GUIDE.md)

## 第二阶段建立评估基线

统一加载策略、执行完整对局、记录结果和重放棋谱。先评估随机合法策略、最短路策略及已有样例模型，用容易理解的局面核对胜负统计。

每个对手固定版本，先后手均衡。行动选择方式也应写明，例如固定使用合法行动中概率最高的动作，或使用已登记种子的随机采样。标准开局和额外合法开局集合分别报告。

初步检查可以从每种对手 100 盘、先后手各 50 盘开始，再依据耗时、结果波动和独特棋谱数量调整。如果双方策略完全确定，同一开局可能反复生成相同棋谱，需要在报告中体现实际覆盖。

评估期间冻结模型参数，保存权重标识、对手、先后手、初始局面、完整行动、终局原因、耗时和种子。用固定开发评估选择模型，最终测试协议另行保留。[可靠性概括](summaries/06_RELIABLE_EXPERIMENTS.md)

## 第三阶段运行现有训练基线

先用短运行检查参数更新、数值、保存加载和评估链路，并测量训练吞吐与内存占用。根据测量制定交互数量和时间预算。

REINFORCE 与模仿学习实验各自保留配置和模型。模仿学习预训练若用于后续强化学习，需要记录样本来源、棋局划分、预训练成本和初始权重，便于分析收益来源。

仓库历史样例包含 26 条专家动作标签，主要用于流程检查。正式数据规模与棋力结论由实验自己的采集和评估记录支持。[REINFORCE 概括](summaries/01_REINFORCE.md)

## 第四阶段接入 PPO

选择并记录具体框架版本，适配棋盘观察、合法掩码、策略预测与评估入口。保存采样时的行动概率，计算回报、价值和优势，对每批经历进行有限轮更新，再用更新后的策略采集下一批经历。

检查采样和更新使用相同局面的合法行动分布，旧概率在本批更新期间保持固定。终局、时间截断和批次边界各按相应语义处理。

首先在相同规则、对手和交互预算下比较当前 REINFORCE 与 PPO，列出必要的网络和算法结构差异。报告学习率、网络、奖励、优化器、采样量和更新次数，便于判断结果来自哪些条件。[PPO 概括](summaries/02_PPO.md) · [行动屏蔽概括](summaries/03_ACTION_MASKING.md)

## 第五阶段安排训练对手

根据实测表现安排随机、最短路、会放墙的启发式或搜索对手，并逐步考虑冻结历史模型。每个阶段记录对手版本、抽样比例、预算和升级条件，一盘棋中固定对手权重。

训练中保留部分旧对手，检查遗忘。固定外部对手持续用于开发评估。评估课程安排时，将早期简单任务成本计入总预算，并与固定混合对手等方案比较。[课程学习概括](summaries/05_CURRICULUM_LEARNING.md)

## 怎样测试模型

### 程序正确性

检查规则边界、行动掩码、先后手、奖励、终止和截断。确认训练会更新参数，评估会保持参数固定。保存加载后，同一局面的行动分布应在数值容差内一致。完整续训还应检验优化器状态和训练计数的恢复。

### 对战表现

| 指标 | 报告内容 |
|---|---|
| 胜、负、截断、错误 | 保存各项数量和明确的结束原因 |
| 总体获胜比例 | 在胜、负、截断这些有效对局中计算获胜比例，并显示分母 |
| 完成局胜率 | 在自然结束的胜负局中计算胜率，同时显示截断情况 |
| 截断率 | 达到上限且未决出胜负的对局比例 |
| 错误率 | 在全部尝试对局中，统计崩溃、非法行动或服务错误 |
| 行为 | 重复局面、放墙次数、关键失误和对局长度 |
| 性能 | 单步决策耗时、训练吞吐、总用时与内存 |

例如，一组测试包含 8 胜、2 负、90 盘截断，报告应同时给出完成局胜率 80%、总体获胜比例 8% 和截断率 90%。这些数字用于说明指标口径。

### 独立训练的可靠性

同一模型的多盘测试，反映该模型在测试条件下的表现。多次独立训练产生的结果，反映训练方法的波动。两种数量都写入报告。

开发探索可以先用少量训练种子，对少量候选增加重复。P4 的图 1 给出筛参阶段至少三次、选定配置后至少十五次的示例流程，其第 7 节也指出三次或五次可能不足以刻画波动。最终运行数量根据目标、差异和实际波动确定，报告全部结果。

训练、开发评估和最终测试分别登记种子与条件。不同候选共用可比较的评估条件，统计时保留训练模型、配对开局和对手这些分组关系。[实证研究设计概括](summaries/04_EMPIRICAL_DESIGN.md)

## 怎样优化模型

| 观察到的现象 | 优先检查 | 可安排的后续实验 |
|---|---|---|
| 长期没有有效进展 | 奖励归属、参数更新、掩码和计分 | 人工短局面诊断，核对完整数据流 |
| 很少获得成功反馈 | 训练对手与当前能力是否匹配 | 调整对手分布或合法初始局面，回到目标任务评价 |
| 对最短路表现好，遇到放墙就差 | 训练局面是否单一 | 加入会放墙的对手，比较课程与固定混合方案 |
| 后手明显较弱 | 目标边、学习方视角、样本数量和截断边界 | 先后手均衡，修复后重建基线 |
| 突然退步 | 采样概率、优势、策略变化、梯度与数值 | 实现正确后，再比较较小学习率或较少更新轮数 |
| 训练奖励上升，胜率变化小 | 奖励塑形是否偏离获胜目标 | 保留原始胜负记录，检查重复移动和拖延 |
| 自我对弈后外部表现下降 | 是否适应过窄的近期对手 | 保留历史和外部对手，按对手检查变化 |
| 训练很慢 | 合法行动与路径搜索、模型推理、日志各占多少 | 测量瓶颈后优化，并检查行为一致性 |

先检验规则与评估，再改善训练经历，接着小范围比较学习率、采样量和更新次数，随后按需要试验网络结构。每轮围绕一个主要假设开展，保留其他条件。对重要因素的相互影响，可以进一步安排小范围组合实验，并为基线投入合理调参预算。[实现细节概括](summaries/07_IMPLEMENTATION_MATTERS.md)

## 最终测试与实验记录

在开发评估中选定模型后，冻结代码、权重、预处理、对手、开局和行动选择方式，再运行保留测试。如果测试反馈继续参与调参，更新记录并安排新的独立评价。

每次运行建议保存配置、代码与依赖版本、训练日志、开发评估、最新与最佳模型、恢复状态、棋谱及结果分析。最终测试保存预先确定的协议、全部结果、各训练种子成绩和复现命令。

棋谱回放按记录的真实行动重新执行，并检查合法性与结局。历史模型试玩产生新对局，两种功能都可以用于观察模型行为。[Agent 工作规范](AGENT_WORKFLOW.md)
