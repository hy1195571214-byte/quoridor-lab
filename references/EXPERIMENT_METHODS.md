# 实施指南：专家棋谱预训练与强化学习微调

2026-11-24 起，现行方案见 [三阶段训练流程](../docs/TRAINING_GUIDE.md#三阶段训练路线)。本文记录此前采用的历史棋谱预训练与强化学习微调方案。

原棋谱基线选定 Expert 对 Expert 与公开 PGN 共 2,500 盘，训练、验证、测试分别为 2,000、250、250 盘。用户已要求排除 Master 数据，已知 Master 对 Master 与 Master 对 Expert 两批整体排除。公开 PGN 档位未知。1.95 GB QuoridorCPP 包已完成下载校验，内容审计后再建立后续数据版本。

后续棋谱发布版本 `round2-cpp208k-v1` 已完成 QuoridorCPP 全量重放检查并新增 208,359 盘合法完局，合计 210,859 盘。原测试分区继续保留，并新增 CPP 保留测试。数据、划分和 GitHub 附件见[合并数据说明](../docs/COMBINED_TRAINING_DATA.md)；下文 2,500 盘方案保留作原基线。

## 训练路线与参考资料

第一阶段用棋盘局面和专家实际行动训练策略网络，方法名称采用“监督模仿学习中的行为克隆（Behavior Cloning）”。“棋谱蒸馏”可用于通俗交流，方法章节写明使用专家动作硬标签。

第二阶段继承预训练策略权重，让模型通过新产生的对局经历和胜负奖励继续学习。AlphaGo（2016）的监督策略预训练、权重初始化和后续策略强化提供主要流程参考。该论文使用 REINFORCE，项目若采用 PPO，其算法依据对应 P2、P3。[P8 研读笔记](summaries/08_ALPHAGO_2016.md) · [完整文献目录](README.md)

GitHub 最新资料还包含采集 Dashboard、样本统计、双远端对战及采集提速记录。采集面板用于观察数据生成，训练曲线与模型评估需要对应的训练记录支持。[Dashboard 说明](../docs/COLLECTION_DASHBOARD.md) · [采集提速与质量记录](../docs/COLLECTION_SPEED_TUNING.md)

## 已确定的设置与当前能力

单盘上限为双方合计 256 次单方行动，一次移动或放墙计一次。第 256 次行动若已产生赢家，按自然终局处理。达到上限仍无赢家时记录为截断。训练环境与 REINFORCE 示例的默认值已统一为 256。

当前沿用标准开局、原始胜负奖励和先后手交替。获胜加一、失败减一，其余通常为零。距离奖励及其组合保留为后续对照实验。

| 组成部分 | 当前内容 | 依据 |
|---|---|---|
| 游戏环境 | 公共规则、8 个 9 行 9 列通道、209 个行动及合法掩码 | [环境](../training/quoridor_lab/env.py) |
| 双远端采集 | 红蓝双方难度、逐步示范、棋谱、缓存和异常记录 | [采集器](../training/quoridor_lab/collect.py) |
| 采集监控 | 当前棋局、历史回放、数据下载及样本统计接口 | [Dashboard](../docs/COLLECTION_DASHBOARD.md) |
| 行为克隆示例 | 读取专家行动、监督训练、按棋局划分训练与验证 | [模仿学习](../training/examples/train_imitation.py) |
| 强化学习示例 | masked REINFORCE，支持加载预训练策略权重 | [策略梯度](../training/examples/train_policy_gradient.py) |
| 后续适配 | 正式数据导入与难度筛选、固定划分、持续训练监控、完整恢复、统一评估、PPO | 依据下述阶段逐项实现与验证 |

现有模仿脚本筛选 `is_teacher=true` 且 `source` 以 `barricade:` 开头的记录。双远端采集会把双方均标为示范，因此 master 对 expert 的两种档位都会通过该筛选。正式预训练需要明确筛选难度，并报告实际进入训练的数量。

## 阶段 A 核对环境与实验约定

检查移动、跳跃、斜跳、墙交叉、墙重叠、禁止封路和胜负。人工设计小局面确定预期结果，随机合法轨迹补充覆盖。先后手都要检查，确保奖励和终局归属正确。

当前一个环境交互通常包含学习方行动和对手回应。分别记录学习方决策次数与双方行动总数。接入 PPO 前，明确达到上限时返回的行动方、最终观察和价值估计。当前环境可能在学习方行动后达到上限并跳过对手回应，结束掩码也会清零。按任务定义处理这些边界并补充测试。

数据导入与行为克隆可以在对应数据和接口检查通过后推进，PPO 的价值估计适配在强化学习接入时完成。阶段产物包括环境约定、测试记录、256 步口径和已知问题。[P4 实验设计](summaries/04_EMPIRICAL_DESIGN.md)

## 阶段 B 合并两台电脑的数据并固定划分

### 导入与质量检查

从已完成批次导出或一致性快照取得文件，为每批记录来源电脑标识、原运行编号、采集时间、代码版本、文件校验值、红蓝难度和上限。合并时用来源与原 ID 形成全局标识，保留可追溯关系。原始数据与处理后数据分别保存，持续采集可以在原电脑继续运行。

联合读取 `episodes.jsonl` 和 `transitions.jsonl`，依据棋局 ID 和步序恢复所属局面。按公共规则重放，检查动作、掩码、观察和结束结果一致。中断恢复的重复记录、缓存样本和同一请求的重试各自统计。

逐步数据中使用 `player` 表示行动方，`metadata.difficulty` 表示该次应手档位，`source` 用于核对来源。元数据缺失或相互冲突时写入导入问题清单，确认后再纳入相应训练分组。`config.remote_sides` 可用于交叉核对红蓝档位。

| 对局来源 | 首版主训练集建议 | 另行保留的信息 |
|---|---|---|
| Expert 对 Expert | 使用去重且通过检查的双方行动 | 请求档位、红蓝方、胜负及原始请求证据 |
| 公开 QuoridorGG PGN | 使用冻结名单中的合法自然完局 | 原始文件、未知玩家身份和档位、推导胜方 |
| Master 对 Master、Master 对 Expert | 按用户决定排除 | 原始批次的来源与审计记录 |

当前数据选择依据用户决定与 [来源白名单](../training/data/datasets/training-selection.json)。网站难度名称按采集元数据记录，实际模型能力仍由对局评价。保留所选来源中胜方和负方的合法示范，并记录结果，后续若选择胜方子集则作为独立数据实验。

当前采集提速说明记录了远端异常 `e2` 应手的问题。非法回复由采集器拒绝，恰好合法的异常回复仍可能进入数据。保留相关重试、拒绝和暂缓日志，按采集窗口、重复行动及代表棋谱抽查质量，训练报告注明相关局限。[质量记录](../docs/COLLECTION_SPEED_TUNING.md)

### 统计与划分

报告自然完局、步数截断、时间截断、未完局及错误数量，再报告独特棋局、独特局面和独特示范数量。按难度、先后手、走棋或放墙、开中残局分别统计。截断或未完局中的已验证行动可用于行为克隆，胜负标签取有自然结果的棋局。

训练、开发验证和最终保留测试按整盘分组，并将重复或近重复完整棋谱归为同组。统计跨集合的局面重合，另行报告未在训练中出现过的局面子集表现。对相同局面的不同合法应手，保留其来源与频次，再决定采样或加权策略。

冻结数据版本和划分清单，记录各组棋局 ID、文件校验值及筛选规则。新到数据建立新版本，原保留测试继续保持独立。观察的步数通道与采集上限有关，统一编码时根据原始棋谱及登记规则重新生成，并保留原始文件。

阶段产物包括数据审计、来源选择后的样本、固定划分清单和小批可重放数据。数据版本及命令以实际导入结果登记。

## 阶段 C 行为克隆预训练与固定评估

先用小批数据验证“读取 → 训练更新 → 保存 → 加载 → 合法行动 → 完整对战”。完整评估入口可与数据导入并行开发。初期保留当前小网络，确定棋盘视角和行动编号，便于后续继承策略权重。

正式训练使用冻结的数据与划分，记录监督损失、保留局面的动作预测表现、走棋与放墙的分项表现及耗时。多次独立运行分别保存模型。示范准确率与完整对战表现共同用于分析模型。

固定模型后对随机、最短路及已接入的启发式或搜索对手评估，先后手均衡，记录胜负、截断、错误和棋谱。保存行为克隆的开发评估最佳快照，作为后续强化学习的起点及长期对照。

现有模仿示例自行按整盘约 80% 训练、20% 验证，并保存最后一轮。正式数据适配需要使实际划分与冻结清单一致，将最终测试留在训练输入之外。自动最佳快照、独立测试和完整训练恢复按开发结果登记。[可运行示例与当前限制](../docs/TRAINING_GUIDE.md)

阶段产物包括预训练配置、数据版本、模型、动作评估、完整对战基线及代表棋谱。进入微调时，保存可复查的初始快照和初始评估。

## 阶段 D 继承预训练权重进行强化学习

先用现有 `train_policy_gradient.py --warm-start` 检查策略权重转移及新对局更新。PPO 目标方案需适配策略网络、观察、掩码、经历收集、价值估计与更新流程。继承时核对实际参数、编码、归一化和行动概率，价值分支的初始化另行记录。

保存行为克隆模型、微调起点与微调后模型。新的强化学习优化器和进度单独初始化，完整中断恢复再读取对应阶段的训练状态。PPO 更新使用当前策略新采集的经历，专家棋谱继续承担监督示范作用。

首轮沿用胜负奖励和 256 次行动上限，记录总交互量、耗时和预训练成本。保留只做行为克隆的模型作对照。资源允许时增加随机初始化强化学习组，匹配强化学习预算并分别报告两阶段总成本。[P8 两阶段训练](summaries/08_ALPHAGO_2016.md) · [P2 PPO](summaries/02_PPO.md) · [P3 掩码](summaries/03_ACTION_MASKING.md)

阶段产物包括权重继承检查、截断边界验证、新采样日志、阶段模型和微调前后的固定评估。

## 阶段 E 对手、课程与奖励组合实验

根据模型弱点增加会放墙的对手、冻结历史策略和固定比例的对手池。整盘固定对手，登记每轮对手版本。保持固定外部评估，观察遗忘和对手适应。

P8 笔记保留了早期多档示范顺序的研究设想。后续课程实验按当前允许的数据来源确定，与相同数据和更新预算下的混合顺序比较。[课程学习](summaries/05_CURRICULUM_LEARNING.md)

奖励组合放在预训练模型和强化学习基线建立之后比较。可以研究胜负奖励、增加自己通路进展、增加阻碍对手的信号及两种信号组合。每组从相同的行为克隆快照出发，固定交互预算、对手、评估和随机种子集合，分别保存模型与日志。

距离启发需要考虑绕路、防守和未来放墙。实现辅助奖励时明确折扣、终局和截断语义，最终依据统一对战表现选择方案。多组并行主要缩短等待时间，先短试跑测资源，再确定同时运行数量。[组件比较](summaries/07_IMPLEMENTATION_MATTERS.md)

## 阶段 F 冻结最终模型并测试

开发评估选好配置和快照后，固定代码、权重、预处理、对手、开局和行动选择方式，运行保留测试。测试反馈若继续用于调参，则登记为开发反馈，并安排新的独立评价。

| 维度 | 报告内容 |
|---|---|
| 示范学习 | 保留棋局和未见局面的动作预测表现，按档位、移动和放墙拆分 |
| 对战能力 | 胜、负、截断、错误及分母，先后手和对手分别报告 |
| 长线行为 | 绕路、防守、放墙时机、重复移动和关键失误的代表棋谱 |
| 可靠性 | 每个独立训练种子的结果、汇总及波动 |
| 成本 | 数据采集、预训练、强化学习、评估各阶段耗时与预算 |

同一模型多盘评估与从头训练多个模型分别统计。P4 图 1 的运行数量是实验流程示例，第 7 节提醒少量运行可能低估波动。候选数量与重复次数根据资源、差异和实际分布确定。[实验设计](summaries/04_EMPIRICAL_DESIGN.md) · [可靠性](summaries/06_RELIABLE_EXPERIMENTS.md)

## 训练监控与保存

当前模仿示例每轮输出指标，REINFORCE 每盘输出指标，并在运行结束后保存模型和指标文件。采集 Dashboard 已提供采集进度与棋谱，训练侧计划增加持续日志、TensorBoard 曲线、定期评估和检查点。

每次运行记录阶段、数据版本、来源配置、代码、依赖、种子和起始模型。行为克隆记录训练与验证曲线，强化学习记录奖励、截断和算法诊断，各阶段都记录固定对战评估。图表标明更新频率，评估胜率随评估批次更新。

保存最新与开发评估最佳模型，记录完整恢复所需的优化器、进度、随机状态和必要预处理。棋谱逐步重放核对合法性与结果。历史模型试玩生成新的对局，历史棋谱用于复查当时行为。[Agent 任务与交付](AGENT_WORKFLOW.md)

## 如何更新本指南与 Reference

每次修改前读取 GitHub 当前版本，登记同步提交并保留已有文献、BibTeX、原文校验信息和采集说明。同步后的新增资料写入目录，并说明与当前实验的关系。本次接入了 P8 AlphaGo、采集 Dashboard 和提速质量记录。

代码实现、数据实测和计划按实际状态记录。新电脑导入数据后更新审计结果，正式开始训练后再填写样本量、模型版本和实测成绩。
